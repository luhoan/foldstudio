## Addendum, 15 November 2026 — where the built thing differs from the brief above

The text above is the original brief and is kept as written. Streams have since
landed, and a few details moved. Where the two disagree, the code and its tests
are the contract; this addendum lists the differences so nobody has to discover
them by reading a diff.

**Recharts is gone.** The brief names it in the stack. The frontend draws its
confidence bands and PAE heatmap directly instead, which removed a dependency
and a chunk of bundle weight. Mol\* is still behind the `ViewerAdapter`
interface, as specified.

**`metrics` is typed `Record<string, unknown>`**, not `Record<string, number |
string | null>`. The client narrows each value where it renders it, which is
safer for a field whose producer is a separate stream. The exporter still only
ever writes flat scalars, and `scripts/hpc_check_contract.py` fails if that
changes.

**Two refusals are load-bearing and tested.** `GET /structures/{id}/plddt`
answers **409** for a structure that is not a declared predicted model —
experimental B-factors occupy the same 0–100 range as pLDDT and would otherwise
be read as confidence. `GET /structures/{id}/pae` answers **404
`pae_unavailable`**, as the brief says. Neither is a gap to fill in.

**Endpoints the brief does not list**, all additive:
`POST /structures/register`, `POST /structures/reindex`,
`POST /structures/{id}/pae` (attach a PAE matrix to an existing structure),
`GET /structures/{id}/interfaces`, and `GET /reports` taking
`format=html|markdown|json`.

**Experiment records carry more than the brief's shape**, again additively:
`metrics_unavailable` (what the run could not measure, and why — these are
absent, not zero), `metric_definitions`, a `workflow` block mapping stages to
what the ledger recorded, and `per_design` rows. Nothing listed in the brief was
removed or renamed.

**`contracts/examples/` is still the shared source of truth for shapes**, and
`frontend/src/api/__fixtures__/` now holds something stronger: nineteen captured
responses from the real backend, regenerated by
`python3 scripts/export_api_fixtures.py` and checked for drift by the same
script with `--check` (and by `backend/tests/test_frontend_fixtures.py`). Hand-
editing a fixture will fail that check; change the API and regenerate instead.

What has and has not actually been executed — especially on the cluster — is in
[`hpc/README.md`](../hpc/README.md#what-has-and-has-not-run). What the last full
review pass changed, and how to undo any part of it, is in
[`FINAL_PASS.md`](FINAL_PASS.md).
